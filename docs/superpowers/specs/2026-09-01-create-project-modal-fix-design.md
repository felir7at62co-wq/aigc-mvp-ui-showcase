# 创建项目悬浮窗修复设计

## 问题

创建项目弹窗当前嵌套在 `.page` 内。`.page` 的 `rise-in` 动画使用 `animation-fill-mode: both`，动画结束后仍保留 `transform`，使后代的 `position: fixed` 以页面内容块而不是浏览器视口作为包含块。再叠加 `.shell-main` 的滚动裁切，造成：

- 遮罩只覆盖项目列表上方的一小段区域；
- 弹窗顶部超出可见区域，剧本文件选择器被导航栏遮挡；
- 页面下方出现大片未被遮罩的白色区域。

## 方案

使用 React Portal 将创建项目弹窗直接渲染到 `document.body`，使弹窗脱离 `.page`、`.shell-main` 及其动画和滚动上下文。

## 交互与布局

- 遮罩固定覆盖整个浏览器视口，位于工作台所有内容之上。
- 弹窗水平、垂直居中，宽度沿用当前桌面布局。
- 弹窗最大高度不超过视口；内容过高时仅弹窗内容滚动。
- 剧本文件选择器位于弹窗首个表单区域，打开弹窗即可看见。
- 点击“取消”关闭弹窗。
- 点击弹窗外遮罩关闭弹窗；点击弹窗内部不关闭。
- 弹窗打开时锁定页面背景滚动，关闭或组件卸载时恢复。
- 保持项目名称自动取剧本文件名、视频尺寸、清晰度、提示词前缀和创建提交逻辑不变。

## 组件边界

- `ProjectsPage` 继续持有表单状态和创建逻辑。
- 新增专用 `CreateProjectModal` 组件，负责 Portal、遮罩、关闭交互和滚动锁定。
- 现有表单内容作为该组件的 children 或显式内容传入，不更改后端 API。

## 测试

- 打开后，弹窗通过 Portal 出现在 `document.body` 下，而不是 `.page` 内。
- 剧本文件输入可见且可交互。
- 点击遮罩关闭，点击弹窗内部不关闭。
- 弹窗打开时背景滚动被锁定，关闭后恢复。
- 原有创建项目 multipart 提交与自动命名测试继续通过。
- 运行完整前端测试和生产构建。

## 非目标

- 不调整项目创建字段和后端数据结构。
- 不修改项目列表、顶部导航或其他页面的视觉风格。
- 不开展 Agent 化开发。
