# 视频生成工作台整合设计

## 目标

把分集选择、分集剧本、镜头脚本、资产匹配、镜头视频生成、视频预览和剪辑轨道整合到一个名为“视频生成”的 Web 页面。项目创建完成后直接进入资产生成；不再显示独立的分集拆分、镜头匹配、转视频或剪辑拼装步骤。

## 已确认布局

应用框架保留全局顶部栏和左侧主流程。主流程精简为：创建项目、资产生成、视频生成、设置。

进入单集视频生成路由后，主体从左到右为：

1. 可上下滚动的分集列表。
2. 与分集列表上下对齐的分集剧本列。
3. 视频生产区。

视频生产区上方从左到右为：镜头脚本、资产匹配、视频预览。下方为横向视频轨道，轨道内保留镜头选择、拖拽排序、裁剪、删除/恢复、转场、替换视频和导出能力。

## 数据与交互

- 分集列表来自现有 `fetchEpisodes`，切换分集通过现有单集路由完成。
- 分集剧本与镜头脚本来自 `fetchShotScript`；完整文本在剧本列展示，时间线片段的 `prompt` 用作镜头摘要。
- 资产匹配来自 `ShotScript.match.shots`，按照当前选中镜头号展示角色、场景和道具；无匹配清单时回退展示时间线片段的 `asset_ids`。
- 视频预览优先显示当前镜头的 `source_video`，没有选中镜头视频时回退到当前分集预览。
- 时间线继续复用 `TimelineEditor`，保存、预览刷新、重新生成、替换、删除、恢复、转场和导出继续使用现有 API。
- 时间线加载后默认选中第一个未删除片段，保证脚本、资产、预览和轨道同步。

## 路由与流程

- 新建项目成功后导航到 `/projects/:projectName?stage=asset`。
- 左侧“视频生成”仍先进入项目仪表盘的 `stage=video`，集列表作为视频生成入口。
- 单集路由 `/projects/:projectName/episodes/:episodeId` 在左侧高亮“视频生成”。
- `prompt`、`shot_match`、`edit` 不再作为用户可见主流程，但后台 API 和任务状态保持兼容。

## 边界与异常

- 缺少时间线时，在底部轨道区显示初始化动作。
- 缺少剧本、资产匹配或视频时，各自面板显示局部空状态，不阻塞其他面板。
- API 错误继续显示在工作台标题下方；不会删除已有后端数据或接口。
- 本次只整合 Web 信息架构和交互，不改视频生成算法及服务端任务协议。

## 验证标准

- 左侧仅显示四个主流程步骤，单集页高亮“视频生成”。
- 创建项目后进入资产生成。
- 单集页按“分集｜分集剧本｜镜头脚本｜资产匹配｜视频预览”排列，视频轨道位于生产区底部。
- 切换分集和镜头时，相应标题、资产和预览同步。
- 原有时间线操作和 API 测试继续通过。
- Web 构建、TypeScript 检查和 Vitest 全量测试通过。
